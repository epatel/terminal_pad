# Project Plan — terminal_pad

## Goal
Build a terminal (TUI) app that presents an infinite 2D canvas the user can paste and edit text on, navigate with arrow keys (Shift jumps the view by one-third of a screen), toggle insert/overwrite with Ctrl+I, and bookmark up to nine canvas locations on Ctrl+1..9 (Ctrl+Shift+1..9 saves the current cursor+view). Ship as a single self-contained binary. *(Keybindings revised from the original F-key idea — see Decisions.)*

## Non-goals
- Rich text / styling (colors, bold) of canvas content — plain characters only (v1).
- Multi-file / tabs / multiple canvases in one session.
- ~~Mouse support~~ (added in M12 — click to position, scroll-wheel pan), networking, collaboration.
- Syntax highlighting or language awareness.
- Undo/redo (deferred; tracked as an open question, not v1).

- [x] **M26 — Ctrl+F find (finds `#tags` too)** — a live search over the canvas. Ctrl+F opens a prompt in the status line (the view deliberately does **not** move until something is typed): each typed char narrows a case-insensitive literal **substring** match *within a row* and jumps the cursor to the first hit in canvas order, Ctrl+F again cycles and wraps, Backspace edits (and closes the search on an empty query), Enter keeps the landing spot, Esc restores the cursor **and** viewport origin. A no-match query holds position and reports it, keeping the query so Backspace can walk back. Unwritten cells read as blanks, so a query with a space matches a typed space or an empty cell alike; overlapping hits each count; a match never wraps rows; char (not byte) offsets keep multi-byte rows correct. There is deliberately **no separate tag feature** — a `#name` tag is just canvas text, so `#api` finds one and a bare `#` walks them all. Jumping uses `viewport::scroll_to_show` when the hit is already visible (so narrowing doesn't shuffle the view) and the new `viewport::focus_on` when it isn't — parking it a **quarter** in from the top-left rather than centering, since the text you want after landing runs below and right. Esc is intercepted in `main::run` before `should_quit`, as the selection guard already was. Ctrl+F is a plain ASCII control code (0x06), so unlike the Ctrl+digit bindings it works in **any** terminal. *First cut was a tag-only search on Ctrl+# — a bad binding, since `#` is Shift+3 on most layouts and collided with Ctrl+Shift+3 = save bookmark slot 3; replaced before release.* New `src/find/` (with CLAUDE.md); `App::search`; a partial `render::draw` branch (canvas still painted, status line becomes the prompt); help overlay gained a row by merging Ctrl+I and Ctrl+B, the panel still fitting 80×24 exactly. 189 tests passing. Done 2026-08-14.
- [x] **M25 — Delete across a leading blank** — fixes Ctrl+D (and insert-mode Delete/Backspace) sticking on a line with spaces. `layout::line_bounds` reaches one column *past* a line's end (the typing position) but nothing *before* its start, and a typed space is "blank" — so once the cursor sat on a leading space it belonged to no line and `pull_line_left` bailed. Repeated Ctrl+D on `ab cd` ran `b cd` → ` cd` → **stuck forever**, and a line merely starting with a space was stuck from the first press (with a char to the left it always worked, since the space was then *inside* the segment). New `layout::line_right_of_blank` covers the missing side: a cursor on a blank claims the segment starting at exactly `cx + 1` — exactly `cx + 1`, because two blanks already separate lines, so content further right is a different line — and the reach is refused when the pull would leave a left-hand neighbour within 2 blanks, so it can never merge two side-by-side columns (the M24 guarantee). `ab cd` now deletes clean through to empty. 173 tests passing. Done 2026-08-14.
- [x] **M24 — Line-aware insert & delete shifting** — fixes ordinary editing destroying a two-column layout. Insert-mode typing and its inverse (Delete/Backspace) called row-wide canvas primitives that shifted *every* cell on the row, so typing in a left-hand column pushed a side column right (`NOTES` at x=20 → 21) and Delete/Backspace dragged it left (→ 19) — the ≥2-blank-gap rule that defines a "line" everywhere else (Enter, Ctrl+K, Ctrl+A/E, Ctrl+D) was ignored by exactly the two most-used keys. Ctrl+D was already correct and is unchanged. Now: right shift → new `layout::open_columns` (the horizontal analogue of `make_room`), which moves only the line under the cursor and, when the shift would squeeze the gap to the next line below two blanks, pushes that line along and **cascades** — so columns keep their separation instead of silently merging into one line; left shift → `editing::pull_line_left`, shared by Delete/Backspace (Insert mode) and Ctrl+D (pulling only widens a gap, so it never cascades). Off a line, Delete still erases the cell rather than no-opping. `calc`/`todo` chained-line prefixes now route through the new `editing::insert_str`, so every write path shares the rule. `canvas::{insert_shift, delete_shift}` — the row-wide primitives that *were* the bug — are **removed** rather than left to be reused. Known adjacent behavior, unchanged: *appending* at a line's end shifts nothing, so a growing line can still walk into its neighbor's gap and merge; only shifting cascades. 163 tests passing. Done 2026-08-14.
- [x] **M23 — Wide (CJK/emoji) character handling** — fixes a real corruption bug: the app's core invariant is *canvas column == screen column* (cursor math, `App::click_to`, selection rectangles all rely on it), but a double-width char covers two terminal columns, so pasting CJK/emoji shifted the rest of the row and put the cursor in the wrong place. Now the **writers** give a wide char two canvas columns — char in the first, truly-blank in the second — and advance by two: `editing::type_char` (Insert pushes the row's tail by two via an `insert_shift` filler at `cx+1` cleared back to blank; Overwrite clears `cx+1`, which the glyph hides) and `editing::paste` (advances `x` by width per char, clearing the shadow column so block placement really does overwrite what it covers). The **renderer** is width-aware to match: `render::window_rows` emits a wide char and **skips the next cell** — so a stale char left in a shadow column by an edit can never push the rest of the row sideways — draws a blank rather than spilling a glyph past the last visible column, and yields rows of `width` *columns* (not chars); `style_row` tracks a column counter instead of `chars().enumerate()`. New single-file `src/width.rs` (`cols`/`is_wide`, via the `unicode-width` crate) is the one source of truth; canvas, layout, selection, persistence, and cursor math are **untouched**. Verified end-to-end against a ratatui `TestBackend` buffer (wide glyph in two cells, following text still on its true column). 152 tests passing. Done 2026-08-14.

## Decisions
- **2026-06-07 — Language/stack: Rust + ratatui + crossterm + serde.** *(Locked)* Reliable Shift+arrow / F-key modifier detection and first-class bracketed-paste come from `crossterm`; `ratatui` handles rendering; single static binary distribution. See [decision-language-rust](cards/decision-language-rust.md). Revisit signal: user prefers C++/Node, or a hard dependency forces a runtime.
- **2026-06-07 — Canvas storage: sparse map keyed by (i64, i64).** *(Locked, pending implementation)* Truly unbounded canvas, only written cells cost memory. See [decision-sparse-grid](cards/decision-sparse-grid.md).
- **2026-06-07 — Location keybindings: Ctrl+1..9 jump / Ctrl+Shift+1..9 save; saves cursor+view.** *(Locked)* Replaces the original F1–F10 idea (Fn keys are unreliable on macOS) → 9 slots. A slot stores both cursor and viewport origin so a jump restores the exact screen state. Caveat: Ctrl+digit modifier reporting needs the Kitty keyboard protocol (kitty/WezTerm/Ghostty/recent iTerm2); plain Terminal.app may not distinguish it. See src/locations/CLAUDE.md.
- **2026-06-07 — Insert/Overwrite toggle: Ctrl+I (was F11).** *(Locked)* Avoids the Fn-key problem on macOS. Caveat: Ctrl+I shares ASCII 0x09 with Tab, so it only toggles in terminals that distinguish them via the Kitty keyboard protocol.
